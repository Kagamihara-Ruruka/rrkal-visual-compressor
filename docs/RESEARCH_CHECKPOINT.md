# Research Checkpoint v1: Defensible Visual Codec

Date: 2026-05-27  
Owner: RRKAL Visual Compressor  
Scope: time-series and 2D-curve preview layers (not full 3D pipeline)

## 1) Core research claim

We are testing one claim only:

> A large, structured visual signal can be represented by a compact model
> (`F`) plus bounded residual layer (`R`) under measurable constraints, so that
> interaction and transport are cheaper than pointwise payloads.

This is a *soundness-first* claim, not a universal guarantee claim.

## 2) Current working hypotheses

1. Global Fourier alone is insufficient for discontinuity-heavy data.
2. Segment-local or hybrid basis choices (piecewise Fourier, local polynomial,
   Haar) reduce locality leakage.
3. Irregular time-domain requires explicit domain encoding policy; raw `x` reuse
   without policy causes drift.
4. Multichannel compression must use shared latent structure (e.g. PCA baseline).
5. Adaptive residual gating can control payload growth in noisy regimes.

## 3) Gate policy for this checkpoint

For every row generated by `scripts/run_defensible_research_sweep.py`:

- `R2 >= r2_gate`  (default `0.99`)
- `leakage_ratio <= leakage_gate` for all three local alternatives
  (default `0.25`)
- `adaptive_keep_ratio <= max_adaptive_keep_ratio` (default `0.45`)

Rows passing all three are marked **defensible = true**.

## 4) Mandatory experiment set

Use the same run with fixed terms and synthetic kinds:

- `steps`
- `spikes`
- `irregular`
- `multiscale`
- `smooth`

Terms baseline:

- `--terms 16,32,64`

This set is fixed until all three gates can be met on at least 40% of rows.

## 5) Minimal stop/advance criteria

Advance only when:

- Reproducible JSON/MD artifacts are generated.
- At least one non-trivial `gate` pass appears in each of
  `steps`, `spikes`, and `irregular`.
- `defensible_rows / rows_with_gate_fields` remains stable across repeated runs
  with identical inputs.

Regress if any of these conditions fail on two consecutive checkpoints.

## 6) What this enables next

After checkpoint success:

- tighten gate defaults;
- add DPI-aware sampling experiments (pixel budget as hard cap);
- add "decode-time cost" and "payload growth under noise" probes in a second
  pass.

The research path stays in this order:

1. **Correctness under measurable constraints**  
2. **Defensible payload governance**  
3. **Viewport-aware runtime study**
